# Bounded local native artifact collection

Profile `testguard.artifact-collector/linux-v1` is an opt-in library read/parse boundary. It is **not** a sandbox, process runner, authenticated collector or production execution permission. CLI `run` remains unavailable. Linux is the only qualified collector platform; other platforms reject. Cargo1.99.0 and Surefire3.5.2 protocol support stays unchanged, with the explicit resource caps below.

`runner::collect::ArtifactCollector::open(root)` pins a caller-selected directory descriptor. Caller owns root/expected-reference selection and protects their authority. The root itself must not be a symlink. Relative artifact paths allow at most32 components/4096bytes and reject empty/dot/dotdot, absolute paths, backslashes, percent-encoded ambiguity and NUL. Each component opens relative to a held directory fd with NOFOLLOW; intermediate components require directories. File opens are NONBLOCK, then fstat requires a regular single-link file. FIFO/devices/directories, symbolic links and hard-linked files are rejected. Renaming/replacing the root pathname cannot redirect the already pinned fd. This does not certify the trust of root's ancestor hierarchy or isolate a hostile process running with host privileges.

Read budget is4MiB per file, with metadata precheck and at most4MiB+1 read to catch growth. Reads perform no writes. UTF-8 is required. Known gzip/ZIP/bzip2/xz/zstd signatures reject and no decompressor exists on this path. Exact expected attempt-relative ArtifactRef size/SHA256 must match bytes; matching a caller-supplied digest proves consistency only, not identity. `collect_batch` permits64requests and16MiB retained bytes, rejects duplicate paths/identities, and retains already collected artifacts alongside per-item errors. `is_complete` means only nonempty byte collection completed; it is never a test verdict, parser success, currentness or authorization. Parsing must still run; any collection/parser error prevents complete execution evidence. The tests show a real native failed report survives alongside a rejected same-size tampered report.

Both parser entrypoints reject output/inventory above4MiB before hashing or building observations. Common limits:64features,16KiB shared executor-scope bytes,4096cases,16KiB native identity bytes,8MiB conservative observation expansion accounting (six times identity+scope bytes plus512bytes per observation). Reservations occur before copying fields/serializing identities. Large otherwise syntactically valid reports become explicit errors, never truncated observations.

JUnit uses a nonrecursive lexical preflight before roxmltree's recursive parse: maximum64element depth,16384markup events,64KiB tag span, complete quoted/comment/CDATA/PI section handling, and no DTD/other declarations. The full pinned parser then enforces grammar with allow_dtd=false and nodes_limit16384; post-parse depth checking remains. Literal markup in comments/CDATA is permitted. External entities are never resolved. Cargo retains its strict inventory/native-count/version/exit checks after common resource admission.

`tests/artifact_security.rs` covers size, identity expansion, XML node/depth/entity/truncation, literal markup, rooted path/symlink/hardlink/FIFO behavior, pinned-root replacement, same-size digest tampering, incomplete batches and retained native failure. `fixtures/security/oversized-report.gz` is real deliberately generated gzip content expanding to8MiB, documented in compression.json; it is an attack fixture, not alleged native tool output. Collection rejects it without decompression.

Not included: process output capture/timeouts/tree cleanup (3.2), OS isolation (3.1), append-only authenticated retention (3.4), arbitrary JSON CLI ingestion budgets, production source authority, or new framework support. Frozen required scope/decision semantics are unchanged.
