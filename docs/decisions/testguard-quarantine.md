# Protected quarantine descriptors

`policy::quarantine` admits a current controller-approved diagnostic quarantine descriptor. It never grants a technical ALLOW, removes an obligation/environment edge, changes FrozenPlan or overwrites mandatory failure/history. Even a valid quarantine leaves the original coverage calculation and retry rules untouched. Replacing obligations requires a separately validated new approved baseline and a new frozen plan; this API cannot approve that replacement.

`QuarantineRequest` requires owner, reason, absolute expiry, approval reference, an alternative safeguard descriptor, and exact frozen obligation/test/environment targets. Unknown or missing JSON fields reject. Alternative description, evidence reference and SHA256 are all mandatory and included in approval identity. **This slice approves that descriptor only. It does not fetch/authenticate the referenced artifact, prove that substitute tests ran, or satisfy a mandatory failure.**

The controller independently supplies `QuarantineAuthority`: native GE EligibilityPolicy, allowed owners, known candidate principals and maximum lifetime. These are protected inputs, not candidate configuration. Candidate principals must be nonempty, and no approval allowlist principal may overlap them. A candidate cannot gain approval by setting a boolean or choosing its own authority lists; protecting those lists and implementing the AuthorityProvider are controller responsibilities. No production provider or automatic principal discovery is installed here.

`ProtectedQuarantine::freeze` checks borrowed counts/lengths before policy cloning or serialization, verifies exact native required scopes and binding against FrozenPlan, and derives a purpose-specific approval action from the entire plan, descriptor, original policy, owner/principal sets, maximum lifetime and freeze time. Native binding retains task/worktree/group as protected policy context; repository/candidate/base/source/baseline/requirements and TestGuard producer profile must match the plan/profile. Full targets include environments. Changing any protected context requires new matching approval.

`authorize` and receipt `refresh` always query GE AuthorityProvider.verify_approval and call GE validate_approval_record. Exact purpose `test.quarantine`, action, binding, contract, principal and current validity must match. Now must not precede freeze, and must be strictly before descriptor expiry. A refreshed receipt additionally rejects time preceding its previous check. Caller supplies trusted time; historical receipts do not discover clock truth or global current policy. Revocation, unavailable authority, expiry and context drift reject; no cached authorization boolean exists.

QuarantineReceipt is opaque and not deserializable. Its serialization is historical audit information (protected/plan digests, checked time, expiry, verified principal), never a current technical verdict. Retain the matching protected request to inspect owner/reason/targets/alternative metadata; refresh against the current ProtectedQuarantine and FrozenPlan on every use. Its methods return no altered plan, CaseStatus, coverage numerator or Decision.

Bounds:64KiB request input;256 targets;256-byte owner/approval/principal/identity strings;4096-byte reason/alternative description/reference and protected context strings;64 members per owner/principal set;4096 required scopes and256 requirements;128KiB total authority text. The existing domain preflight bounds the frozen matrix before hashing. GE remains responsible for its approval-record validation. The configured lifetime is finite and positive, checked with overflow-safe subtraction.

Tests use explicit local fixture authority records and the real GE helper. They cover missing fields, exact environment scope, descriptor/policy/plan drift, self-approval, expiry/revocation/unavailable authority and time regression. Legitimate quarantine leaves required denominator6 and obligations3 unchanged; an actual mandatory failure still yields BLOCK and the existing strict nonzero-exit numerator0. No main `run`, execution sandbox or production eligibility boundary is opened.
