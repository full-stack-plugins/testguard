# Local Linux attempt evidence store

`report::store` provides the opt-in `testguard.store/linux-v1` library profile. A trusted local controller selects an existing private directory, explicit StorePolicy and exact literal redaction values. `EvidenceStore::open` returns the store plus a separate opaque Administration capability. Only that capability can grant namespace Access/RawAuditAccess or purge retained payloads. A client with namespace Access can append, consume or inspect that namespace, but cannot mint another namespace or read raw logs/provenance. Capabilities are process-local, unforgeable through safe Rust constructors and deliberately not deserializable. Reopening the same root issues new capabilities; the controller may reload a serialized immutable Receipt under its newly granted namespace.

This is a controller-owned local store, not external identity authentication, a multiuser service or isolation against malicious code already running with the same Unix uid/root privileges. Root access/distribution and trust in expected receipt bytes are controller responsibilities. Unsigned digests establish consistency only. The store does not evaluate approvals, grant execution, emit GuardEngine eligibility or maintain a current-result pointer. Main CLI run remains unavailable. CLI inputs do not silently pass through this store.

## Admission and immutable publication

The root must belong to the current uid and have no group/other permissions; ordinary0700directories qualify. Linux directory descriptors pin the root; all attempt/file opens use fd-relative NOFOLLOW and NONBLOCK, reject nonregular files/hardlinks/foreign ownership/group permissions and verify exact sizes/digests. Public URI strings are identifiers only, never paths or network destinations. The store uses fixed internal names and a namespace-digest/attempt-digest directory key.

Each append validates the exact FrozenPlan/AttemptRecord plan digest and ordered artifact references, including original attempt association and observation references. Borrowed domain resource preflight runs before serialization or rebuilding a potentially forged matrix. Limits are1MiB each for plan and attempt,64KiB original provenance,4096observations,64artifacts,4MiB per raw/view blob and16MiB aggregate attempt payload. All raw bytes must match their original ArtifactRef. Logs must be UTF8 and cannot substitute for native observation evidence. This validates storage consistency, not the truth of an execution record or whether observations were honestly produced from those reports.

StorePolicy requires a versioned local policy ID, positive evidence lifetime, retention at least that lifetime and at most366days,1–1024attempts, and a positive quota capped at256MiB. Admission reserves a conservative additional1MiB per incoming manifest. Resource limits are explicit deployment choices inside these caps. Busy stores return an error instead of blocking indefinitely. A separately opened lock descriptor/flock serializes concurrent operations across handles/processes; advisory locking assumes all writers use the store API.

Files are created exclusively, synced and set0400. A private staging directory is synced/set0500 and renamed with NOREPLACE into its final key, followed by root sync. A second append for the same namespace/attempt cannot overwrite earlier bytes. Errors remove unpublished staging best effort. Abrupt process death can leave a staging directory, counted against quota; it is never a published receipt or evidence. An I/O error after rename can leave a complete final directory without returning a receipt; retry cannot overwrite it. There is no successful-return claim for failed writes or fsync.

## Evidence, audit and privacy

The immutable manifest records attempt ID, exact plan digest, candidate/base/source/policy binding, approved baseline digest/revision/approval reference, requirement IDs, terminal exit/finished state and pass/fail/skip/unknown observation counts, tool/version, analyzer/version, configuration digest, execution-source reference, optional causal parent, command/environment, approval references, original provenance digest, original artifact references/kinds/digests/sizes, redacted view digests, policy and creation/expiry/retention timestamps. Source/approval/parent references are audit metadata, not authenticated identities or validated retry ancestry; those belong to separate trust/retry tasks.

Plan, AttemptRecord, original provenance and every original artifact remain exact restricted bytes. The original native failure is never rewritten to conceal sensitive log text. Access.consume verifies every required blob freshly and returns the exact plan/attempt plus native Evidence artifacts. It does not return Log bytes or raw provenance. Native evidence/identity metadata may itself contain sensitive data, so grant Access only to principals authorized for the underlying evidence; it is not a universally sanitized public view.

Access.view exposes the audit manifest and redacted log views. All provenance string values and environment keys are redacted; collisions between redacted environment keys reject publication. Matching is longest-first, literal and single-pass, with at most32explicit values of1–1024bytes and bounded view output. Empty values reject; an empty list explicitly disables literal redaction. This does not detect arbitrary secrets automatically. Artifact names, attempt/binding identifiers and native evidence are not rewritten; controllers must not place credentials in public identity fields. RawAuditAccess can separately read exact raw artifacts and original provenance, including sensitive log/command/environment bytes. Preserve that capability at the controller/audit boundary.

`consume` checks controller-supplied current time lies in `[created_at, expires_at)`, reopens and rehashes all required raw/metadata/view blobs, and rejects missing, altered or expired artifacts. It returns byte availability/consistency, not ALLOW. The immutable receipt never extends validity; clock authority and later policy/approval invalidation belong to the controller/task4.5. Audit views remain readable after expiry and show unavailable log views when payloads are gone. After retain_until, Administration plus namespace Access may purge payload files; the original manifest remains unchanged. Audit manifests continue to count against attempt quota, requiring a new store/archive policy when full. No automatic remote deletion or hidden retention default exists.

## Verification

`tests/evidence_store.rs` covers append-only native-failure retention, cross-namespace/store/admin rejection, exact raw versus redacted views, clocks/expiry/purge, missing evidence despite surviving audit, tamper/symlink/hardlink/FIFO rejection, explicit quotas/root permissions, reopen/receipt binding, concurrent duplicate publication and reuse of the existing artifact collector with a captured native JUnit failure. `tests/store_budget.rs` measures allocations around a forged small matrix with a large source expansion; borrowed preflight must reject before cloning. These are real local filesystem tests, not a production storage/provider claim.
