# Controller-owned diagnostic retries

`policy::retry::RetrySession` is a Linux library surface over `EvidenceStore`; it does not spawn processes or enable the disabled main `run` command. A controller freezes a validated plan, execution provenance and maximum1–8 attempts before recording outcomes. Each retry must use a new attempt ID and name the immediately preceding attempt. Tool, analyzer, config, original command/environment, approval refs and complete plan binding remain fixed. Original sensitive provenance is compared by a private digest and retained under the store's raw-audit capability, not returned in summaries.

Every round is appended using the existing bounded private store before its receipt enters immutable session history. Rejected or uncertain append poisons the session: prior successful attempts cannot be exposed as a current successful assessment. Recovery belongs to the controller; this API has no reset/clear/replace operation. Input budgets are checked before digest generation. The store's existing byte, provenance, access and retention limits remain in force.

`assess(now)` freshly consumes all receipts rather than caching success. Missing, expired, modified or inaccessible artifacts reject assessment. Pass→fail and fail→pass classify as flaky and remain BLOCK. Repeated failure remains stable failure; unknown/skip/missing mandatory executions remain incomplete even if a later round passes. Only an all-pass complete history can return local ALLOW. Technical ALLOW grants no execution, approval or merge authority. Required denominators never change.

The durable store preserves bytes and command/environment evidence. The session and its ordered receipt list are in memory and owned by a trusted controller: recreating a session to discard failure history is not a supported workflow. Durable scheduler identity, reconstruction, cross-controller CAS and authenticated production authority are separate tasks. This is an explicit local diagnostic profile, not a claim of autonomous retry orchestration or restart-safe sessions.

Tests cover both mixed orders and repeated failure, raw artifact/provenance retrieval, unique identities, retry bounds, exact parent, changed environment/command/config/plan, partial/skip cases, artifact deletion and expiry. Fixtures are explicitly local observations, not newly executed native tests.
