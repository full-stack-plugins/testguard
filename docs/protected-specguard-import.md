# Protected local SpecGuard obligation import

`PreparedFixtureImport::freeze` freezes independent controller expectations for the exact SpecGuard export bytes, baseline digest, source digest, candidate and requirement scope, plus external test/environment mappings and TestGuard binding. `import` checks the original byte digest before parsing, then verifies baseline/source/scope against those frozen expectations. Candidate edits or later caller mapping changes cannot shrink the resulting private FrozenPlan matrix.

This is explicitly `fixture-only`. A matching digest is consistency evidence, not authenticated identity or current baseline approval. Expectations must come from the protected controller; deriving them from an uploaded/candidate export is not an authorization workflow. Production exports remain rejected by the existing fixture reader. Real authority/expiry/revocation are separate integration work. Existing `import_fixture` remains a clearly untrusted fixture convenience API, now with the same admission limits; it is not a protected consumer entrypoint.

Admission limits are1MiB export bytes before JSON parsing,1MiB serialized mapping/binding expansion accounting,4096 mappings/instances,64 environments per mapping and1,000,000 estimated comparison operations. These are conservative admission budgets, not exact heap/RSS limits. Unknown versions/fields/profile, duplicate/dangling mapping and incomplete source/coverage remain rejected. No incomplete input is trimmed to fit a budget.

`fixtures/integration/specguard-plan/` contains actual output of pinned SpecGuard parser, baseline and export APIs over a real committed Markdown fixture: three obligations, two requirements. The explicit fixture approval adapter is not production authentication. Both environments are protected TestGuard mappings, not claimed native executions. Source bundle, original Markdown, baseline/export bytes, generator and provenance hashes are retained. Tests remove each of six required executions and keep a6-item denominator with BLOCK, reject exact-byte changes and detect rehashed exports that conflict with the frozen baseline/scope/mapping. Raw source and original export are not rewritten during import.
